## 1. Makefile Suitability Audit

### Why a direct `$(AFL_CC) $(SRCS) -o $@` rule cannot build LAVA-M Coreutils

| Reason | Detail |
|--------|--------|
| **Generated config headers** | `./configure` produces `lib/config.h` and `config.h`.  Without them, every one of ~200 Gnulib portability files fails to compile with `#error`. |
| **Intermediate archives** | `libcoreutils.a` and `libgnu.a` are built and linked by the recursive Autotools Makefile.  These cannot be assembled by hand from a flat list of source files. |
| **Autotools-generated sources** | `version.c`, `cu-progs.mk`, etc. are produced during the Autotools build and do not exist on a clean checkout. |
| **NATIVE_CFLAGS conflict** | The existing `NATIVE_CFLAGS` includes `-fsanitize=address`.  Autotools `./configure` self-test programs are compiled with those flags and may fail or produce wrong results.  LAVA-M passes its own `CFLAGS='-g -O2 -DSLOW_BUT_NO_HACKS=1'` separately through the sub-make. |
| **Recursive sub-directories** | Gnulib, `po/`, `tests/`, and `doc/` have their own Makefiles generated by Autotools.  A single-level compile cannot drive them. |

**Design chosen:** Each `lava_<util>` Makefile rule `cd`s into the copy of the Coreutils source tree, runs `./configure`, then delegates to `$(MAKE) -C <tree>`.  It copies the finished binary into `$(BUILD_NATIVE)`.

### Existing Makefile conventions followed

| Convention | How LAVA-M rules follow it |
|------------|---------------------------|
| `$(BUILD_NATIVE)` for output path | All four binaries go to `$(BUILD_NATIVE)/fuzzer_<util>` |
| Phony targets with `@echo` stage messages | All rules use `@echo "[LAVA-M] ..."` |
| Corpus directories under `corpus/` | `corpus/lava_base64/`, `corpus/lava_md5sum/`, etc. |
| Guard recipes with `| $(BUILD_NATIVE)` order-only | Yes, with additional `| $(CORPUS_<UTIL>)` guards |
| `clean_lava` does not wipe unrelated targets | Only removes staged `fuzzer_*` binaries; leaves source trees intact |

## 3. Makefile Additions

The LAVA-M rules were appended to `adaptive-fuzzer/Makefile` after the
`clean` target.  Key additions:

```makefile
LAVA_BASE   := targets/lava_m
LAVA_JOBS   := $(shell nproc)
LAVA_CC     := afl-clang-fast
LAVA_CXX    := afl-clang-fast++
# -DSLOW_BUT_NO_HACKS=1: gnulib portability fix for glibc 2.35+ (see §6)
LAVA_CFLAGS := -g -O2 -DSLOW_BUT_NO_HACKS=1

.PHONY: lava lava_base64 lava_md5sum lava_uniq lava_who clean_lava smoke_lava

lava: lava_base64 lava_md5sum lava_uniq lava_who

$(FUZZER_BASE64): | $(BUILD_NATIVE) $(CORPUS_BASE64)
    cd $(LAVA_BASE)/base64/coreutils-8.24-lava-safe && \
      FORCE_UNSAFE_CONFIGURE=1 CC=$(LAVA_CC) CXX=$(LAVA_CXX) CFLAGS='$(LAVA_CFLAGS)' \
      ./configure --prefix="$$(pwd)/install" --disable-nls
    $(MAKE) -C $(LAVA_BASE)/base64/coreutils-8.24-lava-safe -j$(LAVA_JOBS)
    @test -f ... || (echo "ERROR: binary not found" && exit 1)
    cp ... $@

clean_lava:
    rm -f $(FUZZER_BASE64) $(FUZZER_MD5SUM) $(FUZZER_UNIQ) $(FUZZER_WHO)
```

### Step 7: Build — diagnosis and fixes

**Problem 1:** `make: *** [Makefile:5846: aclocal.m4] Error 127`
- Cause: `cp -r` produces files with the copy timestamp, making `Makefile.in` appear
  older than `Makefile.am`.  Make attempts to regenerate via `automake-1.15`, which
  is absent (`automake 1.16.5` is installed).
- Fix: Replace `build-aux/missing` with a no-op script in each copy.

**Problem 2:** `lib/freadseek.c:68:3: #error "Please port gnulib..."`
- Cause: glibc 2.35+ removed `_IO_ftrylockfile`, which gnulib 2015 used to detect
  GNU libc.  The detection condition fails → the `#else #error` branch fires.
- Fix (freadseek.c, freadahead.c, freadptr.c): prepend `#define SLOW_BUT_NO_HACKS 1`
  before `#include <config.h>` in each file.  Gnulib provides a generic `fseek`-based
  fallback path guarded by this macro.

**Problem 3:** `lib/fseterr.c:81:3: #error "Please port gnulib..."`
- Cause: Same `_IO_ftrylockfile` detection failure; the existing glibc implementation
  (`fp->_flags |= _IO_ERR_SEEN`) was present but unreachable.
- Fix: Extend the `#if` guard to also match `defined _IO_ERR_SEEN`, which IS defined
  in glibc 2.35+ `<stdio.h>` as part of `_IO_FILE`'s `_flags` bitmask.

**Problem 4:** `lib/fseeko.c:113:4: #error "Please port gnulib..."`
- Cause: Same glibc detection, different file.  The POSIX conformance path
  (`FUNC_FFLUSH_STDIN < 0 && 200809 <= _POSIX_VERSION`) exists but the condition
  evaluates false here.
- Fix: Replace the `#error` line with `if (0)` so the lseek-based fallback path below
  (which is always correct) is always used.

## 6. Dependencies, Limitations, and Deviations

| Item | Detail |
|------|--------|
| `libacl1-dev` absent | `libacl1` (shared library) is installed but `libacl-dev` (headers + static lib) is not.  The Coreutils configure script did not require ACL headers for these four utilities; `-lacl` was NOT passed and NOT needed. |
| `bison` absent | Gnulib's `parse-datetime.c` is pre-generated in the LAVA-M corpus copy; bison was never invoked. |
| `automake-1.15` absent | Source trees were generated with automake 1.15; host has 1.16.5.  Fix: `build-aux/missing` replaced with a no-op script in each copy. Original upstream trees are unmodified. |
| glibc 2.35+ gnulib incompatibility | Five gnulib portability files (`freadseek.c`, `freadahead.c`, `freadptr.c`, `fseterr.c`, `fseeko.c`) required patching.  Patches applied only to the copies under `targets/lava_m/`; upstream corpus preserved. |
| `utmp.clean` absent | Not present in LAVA-M corpus.  Canonical utmp seed is at `who/inputs/utmp`; copied to `corpus/lava_who/utmp.clean`. |
| `SLOW_BUT_NO_HACKS` in LAVA_CFLAGS | Added to `LAVA_CFLAGS` in the Makefile; also patched directly into `freadseek.c` et al.  The env var approach was not sufficient because the generated `Makefile` hardcodes `CFLAGS = -g -O2`. |
| `make lava` re-configure behavior | The Makefile rules always re-run `./configure` before building.  If the tree was already configured this re-runs harmlessly.  A future improvement would add a configure-guard file. |
| ARM cross-compile | Not attempted for LAVA-M targets; these are native x86-64 binaries and do not require cross-compilation for fuzzing. |
| AFL++ exit 124 | Expected — from `timeout 35`; fuzzer was killed after 35 seconds, which is the intended short-run mechanism. |
